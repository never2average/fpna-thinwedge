# Governance

ThinWedge is maintained by the repository maintainers for
`never2average/fpna-thinwedge`. Public contributions are welcome through the
process in `docs/contributing.md`, but maintainers retain final responsibility
for product direction, releases, security decisions, and merge decisions.

## Issue triage

Maintainers triage public issues using labels such as `bug`, `enhancement`,
`docs`, `needs triage`, `good first issue`, `help wanted`, `blocked`, and
`security`. Issues may be closed when they are duplicates, cannot be
reproduced, are out of scope, or need to move to the security reporting process.

## Pull request review

External pull requests should be linked to an issue unless they are small
documentation fixes. Maintainers may ask for tests, smaller scope, documentation
updates, or design discussion before review continues.

Accepted pull requests require passing checks, CLA completion, maintainer
approval, and any required CODEOWNERS review. Maintainers squash-merge accepted
pull requests into `main`.

## Releases

Release publishing is maintainer-controlled. Contributor pull requests do not
publish packages. CLI releases are cut from protected release tags after the
maintainers decide a version is ready.

## Security

Security reports, suspected credential exposure, sandbox escapes, and other
sensitive issues must follow `SECURITY.md`. Do not publish exploit details or
private material in public issues or pull requests.
